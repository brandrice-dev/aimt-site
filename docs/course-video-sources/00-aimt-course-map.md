course. Module 12 is an approved *structural* decision only — a course-wide

## Intellectual progression

The course is sequenced so each module's competency becomes the reasoning
foundation for the next: the Welcome Module establishes the standard the
whole course measures against — leading a service versus merely performing
it, and what the eventual certificate does and does not represent — before
any technique is introduced. Module 1 turns that standard into a
professional boundary (observation versus diagnosis, license-dependent
scope, referral judgment) that has to be in place before a practitioner
should be trusted near a real client. Module 2 puts that boundary into
practice at the first point of client contact — arrival, consent, and
hospitality — establishing that professional standards stay consistent even
as the specific ritual adapts. Module 3 then moves beneath the client
interaction into the biology (scalp anatomy, the hair-growth cycle, barrier
function) that gives later observation and assessment work an actual
technical basis rather than guesswork. Each audited module explicitly names
which earlier concepts it revisits (see each module's Guided Completion
Path fields), so the progression is documented module-to-module, not
assumed.

## Approved titles and practitioner payoffs — Modules 0–7

Only these eight modules have a completed, approved audit and manual
approval (`docs/course-audit/modules/module-0{0,1,2,3,4,5,6,7}.md`, each
with an "Approve Module N audit"/manual-approval step in
`implementation-log.md`). Titles and payoffs below are drawn from those
approved specifications.

### Welcome Module (technical Module 0)

**Approved title (student-facing):** Welcome Module
**Hero line:** "Clients can feel the difference between a service that is
being performed and one that is being led."
**Practitioner payoff:** Orients the student to how the course works, what
the certificate actually represents (and doesn't), and the professional
standard — observe before assuming, protect scope, prepare the experience,
adapt responsibly, use tools with restraint — that governs every later
module.

### Module 1 — Role of the Head Spa Technician

**Hero line:** "Know what you are. Know what you are not."
**Practitioner payoff:** Establishes the professional-boundary foundation:
"head spa technician" is a role, not a license; observation is not
diagnosis; scope depends on the student's actual license and jurisdiction;
referral is professional judgment, not failure.

### Module 2 — Welcoming Your Client

**Hero line:** "The experience begins before your hands do."
**Practitioner payoff:** Teaches a repeatable-but-adaptable arrival
framework — intake review, private preparation, optional hospitality,
consent before touch, concise orientation — so professional standards stay
consistent even when the ritual (tea, scent, exact pacing) has to change.

### Module 3 — Hair & Scalp Anatomy

**Hero line:** "What you see is only the surface."
**Practitioner payoff:** Converts anatomy and hair-cycle timing into a
usable decision sequence (structure → visible clue → service implication →
limit), so the student can explain shedding, flaking, and massage honestly
instead of guessing or overclaiming.

### Module 4 — Microscopy & Scalp Assessment

**Hero line:** "Stop assuming. / Start seeing."
**Practitioner payoff:** Teaches a repeatable five-point scalp scan and
five observation lenses so the student can separate a supported visual
observation from a working question and an unsupported conclusion —
giving magnification real diagnostic-adjacent value in a cosmetic setting
without crossing into medical diagnosis. See
[`module-04-video-source.md`](module-04-video-source.md) once that file
exists; it does not yet exist in this repository as of this writing (see
`docs/course-audit/modules/module-04.md` for the full approved
specification in the meantime).

### Module 5 — Scalp Patterns & Service Adaptation

**Hero line:** "Read the pattern. / Adjust the service."
**Practitioner payoff:** Turns Module 4's disciplined observation into a
repeatable service-decision model — identify the safest limit, weigh
client-reported context, then adjust cleansing, exfoliation, water and
steam, pressure and tempo, and product placement by region — replacing the
instinct to force one scalp into one fixed "type" or one uniform
intensity. See
[`module-05-video-source.md`](module-05-video-source.md) for the complete
video-source brief.

### Module 6 — Conditions & Disorders

**Hero framing:** "Module 6 · Conditions & Disorders" — dandruff,
Malassezia, and seborrheic dermatitis, taught as an interpretive judgment
call rather than a condition catalog.
**Practitioner payoff:** Teaches the student to distinguish a dry-scalp
presentation from a dandruff-spectrum presentation using multiple
observable cues together, recognize that appearance is suggestive and not
conclusive, and decide whether the responsible next step is to proceed,
modify, pause, or refer — without diagnosing. See
[`module-06-video-source.md`](module-06-video-source.md) for the complete
video-source brief.

### Module 7 — Equipment & Room Setup

**Hero headline:** "Before the service starts, your setup is already
speaking."
**Practitioner payoff:** Teaches the student to build the physical and
procedural system the rest of the course happens inside — evaluating a
bed by function rather than appearance, organizing a station by
reach-zone and service sequence, and positioning a client using three
concrete checks, including the non-alarmist safety context for why
sustained neck hyperextension is avoided and the stop/adjust/communicate/
resume sequence for a live setup or comfort problem. See
[`module-07-video-source.md`](module-07-video-source.md) for the complete
video-source brief.

## Rules preventing unaudited content from being treated as final

1. A module is final-content authority only when its `module-XX.md` has
   passed an actual approval step (an "Approve Module N audit" entry in
   `docs/course-audit/implementation-log.md`), not merely an extraction
   step. Extraction-only files (`module-XX-source.md`, and any `module-XX.md`
   that still shows empty headings or "Status: Awaiting external audit")
   are not approved content and must not be scripted from.
2. Never use a `module-XX-source.md` file as final authority for any module
   — those preserve the pre-audit experience, including claims and
   terminology the audit removed.
3. Do not manufacture "coming next" continuity for an unaudited module.
   Describe only the approved course-sequence position and any explicit
   handoff line already written into the prior module's approved copy.
4. If a later audit revises a module whose video has already been produced,
   update only that module's video-source file and flag the affected video
   for revision — do not regenerate the whole library on a single module's
   correction (see the "Revision required" status in
   `00-aimt-module-video-master-instructions.md`).
